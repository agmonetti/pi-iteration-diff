# M3 — Selección y transferencia de contexto al editor nativo

**Estado:** Implementado, pulido visualmente y verificado con la suite automatizada (97/97 test suites pass, 0 fallos).

---

## 1. Mecánica de Selección y Prioridad Visual

1. **Selección por teclado:**
   - `Shift + ↑` / `Shift + ↓`: Extiende o contrae continuamente el rango de selección de líneas de diff.
   - `↑` / `↓` estándar: Mueven el cursor y limpian la selección previa si no se pulsa Shift.
   - `Enter` sobre un encabezado de hunk (`@@`): Selecciona instantáneamente todas las líneas de código pertenecientes a ese hunk.
   - `Enter` o `Espacio` sobre una línea de código: Conmuta la selección individual de esa línea.

2. **Selección por ratón:**
   - **Clic:** Selecciona la línea individual de diff (añadida, eliminada o contexto).
   - **Arrastre (Drag):** Arrastrar con botón izquierdo presionado selecciona el rango continuo de líneas abarcado (validado manualmente por humano).
   - **Clic en encabezado de hunk:** Selecciona el hunk completo.

3. **Representación visual refinada de la selección:**
   - **Preservación del separador:** El borde vertical `│` conserva su estilo nativo `border` continuo y no se ve interrumpido por la selección.
   - **Prioridad visual absoluta del fondo:** El contenido de la línea seleccionada aplica el token semántico `selectedBg` (o inversión de vídeo de alto contraste `\x1b[7m...\x1b[27m`), prevaleciendo sobre los colores de adición y eliminación con contraste calibrado para temas claros y oscuros.
   - **Cursor y acento:** El cursor activo sobre una selección se destaca en `accent`, sin generar parpadeos ni solapamientos visuales.

4. **Correspondencia exacta de números de línea:**
   - La selección mapea con exactitud los números `old` (líneas originales) y `new` (líneas nuevas) correspondientes.
   - En selecciones mixtas, el footer refleja ambos rangos en tiempo real:
     - En docks amplios (>= 55 cols): `Sel: old:12, new:12-14 (3 lines) · a: append to editor`.
     - En docks estrechos (< 55 cols): `3 lines selected · a: append`.

## 2. Transferencia de Contexto al Editor Nativo

1. **Acción única `a` (Anexar contexto):**
   - Al pulsar `a`, el fragmento seleccionado se formatea y se anexa al borrador de texto del editor nativo de Pi (`ctx.ui.setEditorText`).
   - No se implementan etiquetas o prefijos `FIX` ni `DISCUSS`.
   - No se incluye ningún prompt prefabricado.
   - **Sin autoenvío:** Jamás se dispara el envío de mensajes. El usuario decide cuándo enviar su instrucción.
   - **Preservación total del borrador:** El texto previo se conserva intacto (`draft ? `${draft}\n\n${snippet}` : snippet`).
   - **Retorno automático de foco:** Tras presionar `a`, el foco vuelve inmediatamente al editor nativo de Pi.
   - **Persistencia del dock:** El panel permanece abierto y los archivos expandidos no se colapsan.
   - **Anexado sucesivo:** Se pueden anexar múltiples fragmentos sucesivamente de uno o varios archivos, separados discretamente por `\n\n`.

2. **Formato de contexto transferido (Texto plano unificado):**
   ```text
   [src/utils/calculator.ts | diff | old:12-14 | new:12-15]
   @@ -12,3 +12,4 @@
    function calculateTotal(items) {
   -  return items.reduce(sum, 0);
   +  const valid = items.filter(Boolean);
   +  return valid.reduce(sum, 0);
    }
   ```
   - **Rutas relativas al workspace:** Nunca absolutas.
   - **Rangos `old/new`:** Derivados fielmente de las líneas seleccionadas (`old:12 | new:12-13`, `new:1-5` o `old:1-4`).
   - **Marcadores de cambio:** Prefijos `+`, `-` y espacio de contexto rigurosamente preservados.
   - **Encabezado `@@`:** Incluido cuando se selecciona un hunk completo.
   - **Sin metadatos ruidosos:** Sin timestamps, IDs, hashes ni caracteres de control peligrosos.

## 3. Protocolo de Validación Humana (Pi Directo y Pi en Herdr)

Este protocolo permite verificar manualmente la experiencia de usuario interactiva:

### Entorno A: Pi TUI Fullscreen directo
1. Ejecutar: `pi --tui-mode fullscreen -e ./src/index.ts`
2. Realizar una petición que modifique archivos (ej. editar una función).
3. Escribir `/diff` para abrir el dock lateral (verificar ancho ~45%, archivos contraídos, dos líneas por encabezado).
4. Presionar `Enter` en el primer archivo (verificar expansión inline con gutter fijo).
5. Seleccionar un rango con `Shift+↓` o arrastrar con ratón.
6. Presionar `a`:
   - Verificar que el fragmento formateado aparece en el editor debajo de cualquier borrador previo.
   - Verificar que el foco regresa al editor para seguir escribiendo.
   - Verificar que no se envía ningún mensaje automáticamente.
7. Redimensionar el dock usando `<` y `>` o arrastrando el separador vertical `│`.

### Retorno de foco con clic en Pi (corrección 2026-10-23)

Con Diff enfocado, un press izquierdo en el transcript, mensaje o espacio vacío
izquierdo devuelve el foco al editor sin anexar ni enviar texto. El clic sobre el
editor conserva su despacho nativo. Rueda, movimiento, drag sin press y release
no cambian foco; los arrastres capturados por Diff/separador siguen en su origen.
La selección del diff se conserva al cambiar de foco. La selección del transcript
sigue las reglas nativas de Pi (un nuevo clic puede reemplazarla).

`ResizableDockRoot.handleMouse` observa sólo eventos no consumidos y retorna
`undefined`: no captura, no reenvía eventos ni modifica componentes nativos.
Contrastado con Pi/TUI 1.4.0 (`dispatchMouseToLayout`, `handleMouseEvent` y
`dispatchMouseEvent`): el hit-path se recorre de hijos a root; un resultado de
mouse consumiría el press y borraría la selección nativa. Los listeners públicos
de input se ejecutan después del listener del viewport que consume el mouse;
no sirven como observador previo. `MouseRegion` tampoco observa hijos que consumen.

**Límite deliberado:** controles nativos que consumen el evento, scrollbars,
buscador y overlays tienen prioridad y pueden no devolver foco al editor. No hay
un hook público de observación previa para cubrirlos sin interceptar internals;
se conserva su interacción antes que imponer foco. Alternativa: `Esc` desde Diff
o clic en el editor. No se promete literalmente cualquier control nativo.
Sin monkey-patching global ni cambios a Pi/Herdr.

Regresiones: `tests/native-pane-focus.test.ts` usa el renderer real con SGR
sintético y comprueba foco, borrador, contador de envíos, selección/copia nativa,
enlace OSC 8, rueda y captura cruzada de resize/selección. Esto no certifica
mouse físico ni el transporte de Herdr.

**Revalidación humana pendiente (NOT RUN en esta corrección):** en ambos entornos,
registrar Node/Pi/Herdr/terminal, dejar un borrador y rango seleccionado, alternar
clics en transcript/mensajes/vacíos/editor/Diff, seleccionar/copiar texto, abrir
un enlace, usar rueda y arrastrar separador/rango cruzando al lado izquierdo.
Verificar ausencia de envío y cambios al borrador; los gestos nativos deben
conservar su comportamiento. El DoD físico sigue pendiente de este resultado.
