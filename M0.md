## Prueba humana pendiente

Desde un terminal común, y después dentro de un pane de una **instancia de prueba** de Herdr:

```bash
extension="$PWD/src/index.ts"
sandbox="$(mktemp -d)"
# No cerrar este shell hasta terminar la prueba. Los temporales se borran al salir.
trap 'rm -rf -- "$sandbox"' EXIT
mkdir "$sandbox/agent" "$sandbox/workspace"
cd "$sandbox/workspace"
PI_CODING_AGENT_DIR="$sandbox/agent" PI_TELEMETRY=0 pi \
  --offline --no-session --no-extensions --no-mcp --no-skills \
  --no-prompt-templates --no-context-files --tui-mode fullscreen -e "$extension"
```

1. Confirmar panel inicialmente oculto; `/m0-diff` abre/cierra. El contenido dice
   **SYNTHETIC**, no representa archivos del workspace. No se registra `/diff` aún.
2. Escribir un borrador; `F6` enfoca el panel. Flechas mueven, Shift+flecha amplía;
   `a` agrega el fragmento sintético al final, dos veces conserva ambos. Esc/Tab vuelve
   al editor. No enviar el mensaje; comprobar borrador literal y edición nativa.
3. Mouse press/drag/release sobre las tres líneas; repetir invertido. Arrastrar hacia
   la izquierda y soltar: el indicador registra entrega fuera del panel, **no un drop
   al editor**. La API entrega coordenadas negativas relativas al panel capturante.
4. Reducir a menos de 90 columnas: panel oculto y foco devuelto al editor; volver
   a ampliar. Probar altura pequeña, scroll del chat, rueda, foco y escritura.
5. Abrir panel y ejecutar `/reload`, `/new`, `/resume`; comprobar recuperación. Probar
   Ctrl+C (limpieza nativa del borrador) y Ctrl+D (salida). No se intercepta Ctrl+C.
6. Repetir en Herdr: sidebar, split, zoom, resize y detach/reattach. Registrar cliente
   terminal real y dimensiones. Cargar la integración oficial explícitamente sólo en
   el pane de prueba (`-e /ruta/a/herdr-agent-state.ts`); nunca reinstalarla.
7. En una sesión de prueba autorizada con modelo, usar `/m0-events` después de una
   petición con write/edit/bash y varios turnos; repetir con colas, retry y aborto.
   El probe retiene sólo 100 nombres de eventos, nunca prompts ni contenido de código.

## Alcance de las decisiones

- Composición con HStack/VStack/ScrollView públicos; acceso interno a `layoutRoot`
  y `getFocusedComponent` únicamente en `src/ui/layout-adapter.ts`.
- Reconocimiento conservador del árbol nativo de `createChatViewport` por referencias
  de componentes. No es un protocolo universal de ownership. Un root desconocido se
  rechaza con aviso; no hay fallback modal que se haga pasar por dock.
- Cleanup restaura sólo mientras conserva ownership. El widget público proporciona
  acceso al TUI y disposal; no reemplaza editor, footer ni header.
- Umbral 90 y ancho 34 son valores experimentales del spike, no diseño final.
- `getEditorText()` + `setEditorText()` síncronos preservan el texto al anexar al final;
  no garantizan conservar cursor/undo. No se llama a sendUserMessage/pasteToEditor.
- Lifecycle: source confirma before_agent_start antes del modelo/herramientas del run,
  pero después del chequeo de compaction; los handlers de extensiones anteriores pueden
  tener efectos. Input/steering/follow-up no equivalen uno a uno a before_agent_start.
  **No está cerrado el contrato de iteración** sin trazas reales de colas/reintentos.

M0 sigue abierto. No hay snapshots, parser de diff, historial, feedback old/new real,
ni instalación/distribución. No avanzar a M1 hasta completar su matriz y ADR.

## Contrato M0 de iteración: decisión y límite explícito

Una petición aislada aceptada mientras Pi está idle, más su continuación automática,
es una iteración lógica candidata. Herramientas, turnos internos y retries no crean
nuevas iteraciones. `turn_end` y `agent_end` nunca son cierre definitivo.

| Señal / situación | Contrato para la futura captura (no implementada en M0) |
|---|---|
| Input idle aceptado | Candidato a inicio; confirmar que dispara before_agent_start, no un comando/entrada consumida |
| Baseline | Antes de efectos del run; input es el hook temprano a investigar, before_agent_start ya ocurre tras compaction. Orden de otros handlers puede impedir garantía total: marcar incompleta, no atribuir certeza |
| turn_end / agent_end / retry | Mantener la misma ventana; no finalizar ni renovar baseline |
| agent_before_settle | Puede pedir continuación; todavía no finalizar; abort puede omitirlo |
| agent_settled false | Cierre automático de ventana, completo sólo si baseline/alcance son válidos y no hay ambigüedad de entradas |
| agent_settled true | Cancelada/parcial, nunca una petición completada normal |
| Steering/follow-up explícito durante la ventana | Marcar ventana **agrupada/ambigua**; puede compartir settled con el input anterior. No inventar deltas individuales ni llamarla última petición |
| Sesión/worktree distinto, reload o cierre | Invalidar captura activa anterior y limpiar UI; no reutilizar baseline/selección. Restore de conversación no implica restore de snapshots |

**Decisión de seguridad semántica:** no equiparar idle→settled con una petición si
hubo entradas explícitas encoladas. Para esos casos el producto debe poder identificar
una frontera adicional demostrada o declarar que el delta individual no está disponible;
no presentar un grupo ni un resultado antiguo bajo la etiqueta Last iteration.
No se implementa una política de snapshots ahora. La indisponibilidad para colas no
es una excepción FR-03 aprobada: queda como bloqueo de aceptación de M0/ADR-003 hasta
probar separación individual o recibir aprobación explícita de ese límite. No cambia
la definición de petición en REQUIREMENTS.md ni permite avanzar a M1 por sí sola.

## Evaluación acotada de drag literal y matriz de salida actual

El API público `TuiMouseEvent` entrega x/y locales y screenX/screenY absolutos;
`capture` retiene drag/release en el panel. Esto ofrece una vía de experimento, no
una prueba de drop al editor. `TuiMouseEventResult` no define un payload de drop.
El spike actual modifica cursor por y local mientras arrastra, y en release sólo
registra `x < 0`: no identifica editor vs conversación ni conserva un rango congelado
para transferir. Por ello el resultado humano (copia/no transferencia) es esperable
sin demostrar bloqueo del terminal. No se añaden internals ni un mecanismo M3.

Próximo experimento mínimo, pendiente: congelar un rango seleccionado; observar
press/drag/release con screenX/Y en el límite y región del editor, incluyendo resize;
probar identificación de destino sin editar controles nativos. Sólo si esa entrega
es fiable en Pi y Herdr, anexar por acción drop explícita y repetir preservación del
borrador. No inferir destino sólo por x negativa ni aprobar paridad desde SGR fake.
Mientras tanto seleccionar → `a` es funcionalidad humana validada, no drop literal.

### ADR-003 confirmado: ventana observable, no atribución individual garantizada

**Política concreta para M1, no implementación en M0.** La API pública no da un
request ID causal que vincule cada escritura a una petición. Sí permite observar
entrada y settlement; varias peticiones pueden compartir un settlement.

1. Identidad: `(sessionId, realpath(worktreeRoot), runtimeEpoch, sequence)`.
   `runtimeEpoch` nuevo por carga de extensión; `sequence` monótono local por
   candidato. Guardar ordinales de entradas, no prompts ni código en logs. Un grupo
   conserva un ID de ventana y ordinales miembros, no snapshots individuales ficticios.
2. En `input` sin ventana activa, abrir candidato y esperar baseline acotado antes
   de devolver `continue`. Es anterior al procesamiento del agente, no a handlers
   anteriores ni a procesos externos. Si falla o excede límites, baseline parcial.
   Confirmar candidato en `before_agent_start` de tipo user. Si otra extensión
   consume el input o falla preflight, no publicar captura completada; descartar
   candidato no confirmado antes del siguiente inicio. No usar texto igual como ID.
3. Si `before_agent_start` no tiene candidato correlacionable, abrir baseline allí
   y marcar **inicio tardío/no verificable**; no publicarlo como delta individual
   completo. Tipo custom no es petición humana; mantenerlo explícitamente separado
   o marcar ambigüedad si se incorpora a una ventana humana.
4. Con ventana activa, cualquier nueva entrada potencialmente explícita marca la
   ventana agrupada/ambigua de manera conservadora, aunque luego pueda consumirse
   sin ejecutar. `input.streamingBehavior` distingue `steer`/`followUp` cuando está
   disponible; `source` sólo interactive/rpc/extension. No hay confirmación pública
   universal de aceptación/consumo y correlación para cada cola. Mensajes user
   adicionales observados por `message_start` también invalidan individualidad
   (cubren entradas no vistas por input); no inferir autoría desde su texto.
5. `turn_end`, `agent_end`, retry de proveedor/AgentSession, compaction y continuación
   desde `agent_before_settle` mantienen la misma ventana y baseline. Retry manual
   tras settlement es candidato nuevo, no continuación retrospectiva.
6. `agent_settled` cierra: esperar captura final acotada y finalizar estado antes
   de aceptar otro candidato. `aborted=true` → cancelada/parcial; error definitivo
   o captura incompleta → parcial/error, aun con `aborted=false` (no significa éxito).
   Sin ventanas abiertas, settled no inventa una iteración. No depender de
   `agent_before_settle` para cleanup: abort puede omitirlo.
7. Si varias entradas comparten settled, conservar sólo delta neto **de ventana
   agrupada**, etiquetado como tal, nunca dividir por turnos o herramientas.
   `Last iteration` individual queda **indisponible: peticiones agrupadas**, no
   mostrar el grupo ni una petición anterior bajo esa etiqueta. No abrir baseline
   al consumir cada follow-up: no hay quietud del filesystem demostrada.
8. `session_shutdown` invalida captura/UI; `session_start` crea scope limpio.
   Cambio de sesión/worktree y `/reload` invalidan referencias; reabrir una sesión
   conserva ID de conversación, no snapshots efímeros. Trabajos async deben validar
   scope/epoch antes de publicar. Capturas no atómicas frente a escritores externos:
   anunciar siempre delta observado, no autoría garantizada.

Comprobabilidad: L1 prueba múltiples turnos/herramientas; L2/L3 prueban dos entradas
bajo un settled; L4 HTTP prueba retry sin renovar before_agent_start; L5 abort
prueba cierre cancelado sin before_settle; L6 prueba identidad/restauración SDK.
Las transiciones de candidatos, serialización before/after, señales de mensajes no
correlacionados y estados UI de indisponibilidad deben tener tests en M1; **no están
implementados ni aprobados por los 14 tests actuales**. Si la API no permite probar
una correlación, degradar a ambigua/parcial, nunca certificar una petición.

Esta política resuelve la decisión arquitectónica M0; no relaja FR-03 ni supone
excepción aprobada. Cobertura individual de colas sigue siendo limitación/riesgo de
producto a decidir antes de aceptar M1, no motivo para seguir experimentando sin fin
en M0. La indicación histórica de «frontera o excepción para ADR-003» queda sustituida
por esta política explícita de indisponibilidad, no por una garantía inventada.
