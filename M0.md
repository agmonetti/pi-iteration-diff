# M0 — Spike reproducible (no es el producto)

Probado el 2026-10-22: Linux 7.2.11-arch1-1, Node 26.12.0, npm 12.2.1,
Pi 1.4.0, Herdr 0.9.5. El harness corre dentro de Herdr, pero sus comandos bash
no tienen stdin TTY. Una PTY creada por Python no equivale al mouse físico del cliente Herdr.

## Automatización

```bash
npm ci --ignore-scripts
npm run check
python3 tests/pty-smoke.py
```

La suite usa el renderer real `@earendil-works/pi-tui@1.4.0` con terminal simulado.
El smoke ejecuta el **CLI instalado**, con directorio de agente y cwd temporales,
sin extensiones descubiertas, credenciales, sesiones persistidas, MCP ni llamadas a modelos.
Se borran los temporales al salir. No modifica el índice Git ni la instalación de Pi/Herdr.
El proyecto usa dependencias de desarrollo; la extensión no requiere un proceso nuevo.

## Prueba humana pendiente

Desde un terminal común, y después dentro de un pane de una **instancia de prueba** de Herdr:

```bash
extension="$PWD/src/index.ts"
sandbox="$(mktemp -d)"
# No cerrar este shell hasta terminar la prueba. Los temporales se borran al salir.
trap 'rm -rf -- "$sandbox"' EXIT
mkdir "$sandbox/agent" "$sandbox/workspace"
cd "$sandbox/workspace"
PI_CODING_AGENT_DIR="$sandbox/agent" PI_TELEMETRY=0 pi \
  --offline --no-session --no-extensions --no-mcp --no-skills \
  --no-prompt-templates --no-context-files --tui-mode fullscreen -e "$extension"
```

1. Confirmar panel inicialmente oculto; `/m0-diff` abre/cierra. El contenido dice
   **SYNTHETIC**, no representa archivos del workspace. No se registra `/diff` aún.
2. Escribir un borrador; `F6` enfoca el panel. Flechas mueven, Shift+flecha amplía;
   `a` agrega el fragmento sintético al final, dos veces conserva ambos. Esc/Tab vuelve
   al editor. No enviar el mensaje; comprobar borrador literal y edición nativa.
3. Mouse press/drag/release sobre las tres líneas; repetir invertido. Arrastrar hacia
   la izquierda y soltar: el indicador registra entrega fuera del panel, **no un drop
   al editor**. La API entrega coordenadas negativas relativas al panel capturante.
4. Reducir a menos de 90 columnas: panel oculto y foco devuelto al editor; volver
   a ampliar. Probar altura pequeña, scroll del chat, rueda, foco y escritura.
5. Abrir panel y ejecutar `/reload`, `/new`, `/resume`; comprobar recuperación. Probar
   Ctrl+C (limpieza nativa del borrador) y Ctrl+D (salida). No se intercepta Ctrl+C.
6. Repetir en Herdr: sidebar, split, zoom, resize y detach/reattach. Registrar cliente
   terminal real y dimensiones. Cargar la integración oficial explícitamente sólo en
   el pane de prueba (`-e /ruta/a/herdr-agent-state.ts`); nunca reinstalarla.
7. En una sesión de prueba autorizada con modelo, usar `/m0-events` después de una
   petición con write/edit/bash y varios turnos; repetir con colas, retry y aborto.
   El probe retiene sólo 100 nombres de eventos, nunca prompts ni contenido de código.

## Alcance de las decisiones

- Composición con HStack/VStack/ScrollView públicos; acceso interno a `layoutRoot`
  y `getFocusedComponent` únicamente en `src/ui/layout-adapter.ts`.
- Reconocimiento conservador del árbol nativo de `createChatViewport` por referencias
  de componentes. No es un protocolo universal de ownership. Un root desconocido se
  rechaza con aviso; no hay fallback modal que se haga pasar por dock.
- Cleanup restaura sólo mientras conserva ownership. El widget público proporciona
  acceso al TUI y disposal; no reemplaza editor, footer ni header.
- Umbral 90 y ancho 34 son valores experimentales del spike, no diseño final.
- `getEditorText()` + `setEditorText()` síncronos preservan el texto al anexar al final;
  no garantizan conservar cursor/undo. No se llama a sendUserMessage/pasteToEditor.
- Lifecycle: source confirma before_agent_start antes del modelo/herramientas del run,
  pero después del chequeo de compaction; los handlers de extensiones anteriores pueden
  tener efectos. Input/steering/follow-up no equivalen uno a uno a before_agent_start.
  **No está cerrado el contrato de iteración** sin trazas reales de colas/reintentos.

M0 sigue abierto. No hay snapshots, parser de diff, historial, feedback old/new real,
ni instalación/distribución. No avanzar a M1 hasta completar su matriz y ADR.

## Lifecycle — protocolo reproducible pendiente, no traza ejecutada

No se obtuvieron trazas nuevas con modelo en este bloque. La suite y la PTY no
cubren estos casos. Preparar un fixture nuevo por caso; no usar sesiones personales.
Desde el directorio del proyecto en un shell humano:

```bash
extension="$PWD/src/index.ts"
sandbox="$(mktemp -d)"
chmod 700 "$sandbox"
mkdir "$sandbox/agent" "$sandbox/workspace" "$sandbox/sessions"
cd "$sandbox/workspace"
# Sin --offline ni --no-session: requiere proveedor/modelo autorizado de prueba.
# No copiar auth.json personal. Autenticar sólo si el operador lo autoriza.
PI_CODING_AGENT_DIR="$sandbox/agent" PI_TELEMETRY=0 pi \
  --session-dir "$sandbox/sessions" --no-extensions --no-mcp --no-skills \
  --no-prompt-templates --no-context-files --tui-mode fullscreen -e "$extension"
```

No borrar el sandbox hasta terminar resume y transcribir las trazas saneadas;
eliminarlo después desde el shell que conserva la variable. El runtime persistirá
mensajes/código sintético en ese directorio privado aunque el probe sólo guarde
nombres. No versionar sesiones, credenciales ni transcripciones completas.

1. **L1 / múltiples turnos internos — NOT RUN.** Nueva sesión: enviar exactamente
   `Usá write para crear m0.txt con uno; después edit para cambiarlo a dos; después
   bash para ejecutar printf tres > m0.txt. Hacé cada herramienta en un turno
   separado y al final respondé listo.` Al quedar inactivo ejecutar `/m0-events`.
   Copiar secuencia y comprobar tres pares de herramientas y varios `turn_start/end`.
   Si el modelo agrupa llamadas, el caso NO demuestra múltiples turnos: repetir
   controladamente; no convertir la secuencia esperada en evidencia.
2. **L2 / steering — NOT RUN.** Pedir `Ejecutá bash sleep 15; después escribí
   m0-steer.txt con original`. Mientras duerme, enviar con Enter `En lugar de
   original escribí steering`. Esperar settled y consultar `/m0-events`. Registrar
   cuándo se tecleó y cuándo se consumió la cola; no inferirlo sólo de `input`.
3. **L3 / follow-up — NOT RUN.** Repetir sleep en sesión nueva. Durante la espera
   escribir `Creá m0-followup.txt con followup` y pulsar Alt+Enter (default Linux
   instalado; verificar keybinding activo si el terminal lo intercepta). Registrar
   cola visible, ejecuciones y `/m0-events` al terminar. Comparar L2/L3.
4. **L4 / retry automático — NOT RUN.** Requiere proveedor de prueba controlado:
   primera respuesta HTTP 429 transitoria y segunda éxito, usando un endpoint local
   sin credenciales reales. El fixture de proveedor aún NO existe. Registrar número
   de solicitudes, estado y orden de eventos, sin headers/prompts. No simular retry
   con un error de herramienta ni fallar deliberadamente un proveedor personal.
   Retry manual tras error definitivo es otro caso, no sustituye éste.
5. **L5 / aborto — NOT RUN.** Pedir `Ejecutá bash sleep 30 y luego creá
   m0-abort.txt`. Durante sleep pulsar Escape para abortar; registrar señal efectiva,
   estado de la herramienta y `/m0-events`. Comprobar `agent_settled:aborted=true`,
   ausencia/presencia real del archivo y que un nuevo prompt vuelve a settled normal.
   Probar Ctrl+C aparte; no asumir que equivale a abortar, puede limpiar el editor.
6. **L6 / restauración — NOT RUN.** Tras L1 guardar `/m0-events`, cerrar Pi y
   relanzar el mismo comando con `--resume`. Elegir sólo la sesión del fixture.
   Consultar eventos antes de enviar otro prompt; luego ejecutar una petición nueva.
   Repetir con `/new`, `/resume` y `/reload` con dock abierto. Registrar por separado
   antes/después: `session_start` vacía el buffer y `session_shutdown` lo borra;
   el probe NO conserva una traza de shutdown ni correlación persistente.

**Límite del instrumento:** buffer de 100 entradas, sin ordinal/timestamp/session ID,
ni eventos específicos de retry/consumo de cola. `input.source` no es un identificador
steering/follow-up. Comparar observación humana y fixture, no atribuirle al probe más
información de la que emite. Si se supera el límite, marcar traza incompleta. Separar
por caso y sesión; no mezclar trazas de dos ejecuciones. Hace falta instrumentación
adicional antes de confirmar ADR-003; baseline/final no se implementan en M0.

**Gate:** H1–H8 y L1–L6 siguen pendientes; no certificar Pi/Herdr ni cerrar M0.
