# M3 — Selection and Context Transfer to Native Editor

**Status:** Implemented, visually polished, and verified with automated suite (97/97 test suites pass, 0 failures).

---

## 1. Selection Mechanics and Visual Priority

1. **Keyboard selection:**
   - `Shift + ↑` / `Shift + ↓`: Continuously extends or collapses diff line selection range.
   - Standard `↑` / `↓`: Move cursor and clear prior selection if Shift is not pressed.
   - `Enter` on a hunk header (`@@`): Instantly selects all code lines belonging to that hunk.
   - `Enter` or `Space` on a code line: Toggles individual selection of that line.

2. **Mouse selection:**
   - **Click:** Selects individual diff line (added, deleted, or context).
   - **Drag:** Dragging with left button pressed selects spanned continuous line range (manually validated by human).
   - **Hunk header click:** Selects entire hunk.

3. **Refined visual representation of selection:**
   - **Dock border:** Side border and prefixes use `▏`, accent when panel has focus and dim when unfocused; top row `🭽` + `▔` maintains focus width and color without altering panel useful height.
   - **Absolute visual priority of background:** Selected line content applies semantic token `selectedBg` (or high-contrast video inversion `\x1b[7m...\x1b[27m`), prevailing over addition and deletion colors with calibrated contrast for light and dark themes.
   - **Cursor and accent:** Active cursor over selection highlighted in `accent`, without generating flicker or visual overlap.

4. **Exact line number correspondence:**
   - Selection maps accurately corresponding `old` (original lines) and `new` (new lines) numbers.
   - In mixed selections, footer reflects both ranges in real time:
     - In wide docks (>= 55 cols): `Sel: old:12, new:12-14 (3 lines) · a: append to editor`.
     - In narrow docks (< 55 cols): `3 lines selected · a: append`.

## 2. Context Transfer to Native Editor

1. **Single action `a` (Append context):**
   - Upon pressing `a`, selected snippet is formatted and appended to Pi native editor text draft (`ctx.ui.setEditorText`).
   - No `FIX` or `DISCUSS` tags or prefixes implemented.
   - No prefabricated prompt included.
   - **No auto-sending:** Message sending is never triggered. User decides when to send instruction.
   - **Total draft preservation:** Prior text kept intact (`draft ? `${draft}\n\n${snippet}` : snippet`).
   - **Automatic focus return:** After pressing `a`, focus returns immediately to Pi native editor.
   - **Dock persistence:** Panel remains open and expanded files do not collapse.
   - **Successive appending:** Multiple snippets can be appended successively from one or several files, discretely separated by `\n\n`.

2. **Transferred Context Format (Unified plain text):**
   ```text
   [src/utils/calculator.ts | diff | old:12-14 | new:12-15]
   @@ -12,3 +12,4 @@
    function calculateTotal(items) {
   -  return items.reduce(sum, 0);
   +  const valid = items.filter(Boolean);
   +  return valid.reduce(sum, 0);
    }
   ```
   - **Workspace-relative paths:** Never absolute.
   - **`old/new` ranges:** Faithfully derived from selected lines (`old:12 | new:12-13`, `new:1-5` or `old:1-4`).
   - **Change markers:** `+`, `-` prefixes and context spacing rigorously preserved.
   - **`@@` header:** Included when a full hunk is selected.
   - **No noisy metadata:** No timestamps, IDs, hashes, or dangerous control characters.

## 3. Human Validation Protocol (Standalone Pi and Pi in Herdr)

This protocol allows manually verifying interactive user experience:

### Environment A: Direct Fullscreen Pi TUI
1. Run: `pi --tui-mode fullscreen -e ./src/index.ts`
2. Make a request modifying files (e.g., edit a function).
3. Type `/diff` to open side dock (verify width ~45%, collapsed files, two lines per header).
4. Press `Enter` on first file (verify inline expansion with fixed gutter).
5. Select a range with `Shift+↓` or drag with mouse.
6. Press `a`:
   - Verify formatted snippet appears in editor below any prior draft.
   - Verify focus returns to editor to continue writing.
   - Verify no message is sent automatically.
7. Resize dock using `<` and `>` or dragging vertical separator `│`.

### Focus Return with Click in Pi (Correction 2026-10-23)

With Diff focused, left press in transcript, message, or left empty space
returns focus to editor without appending or sending text. Click on editor
preserves native dispatch. Wheel, move, drag without press, and release
do not change focus; drags captured by Diff/separator remain at origin.
Diff selection is preserved upon focus switch. Transcript selection
follows Pi native rules (new click may replace it).

`ResizableDockRoot.handleMouse` observes only unconsumed events and returns
`undefined`: does not capture, forward events, or modify native components.
Contrast with Pi/TUI 1.4.0 (`dispatchMouseToLayout`, `handleMouseEvent`, and
`dispatchMouseEvent`): hit-path traversed from children to root; mouse result
would consume press and erase native selection. Public input listeners
executed after viewport listener consuming mouse; do not serve as prior
observer. `MouseRegion` also does not observe consuming children.

**Deliberate limit:** native controls consuming event, scrollbars,
searcher, and overlays take precedence and may not return focus to editor. No
public prior observation hook exists to cover them without intercepting internals;
their interaction is preserved before imposing focus. Alternative: `Esc` from Diff
or click in editor. Does not promise literally any native control.
No global monkey-patching or changes to Pi/Herdr.

Regressions: `tests/native-pane-focus.test.ts` uses real renderer with synthetic
SGR and checks focus, draft, send counter, native selection/copy,
OSC 8 link, wheel, and crossed capture of resize/selection. This does not certify
physical mouse or Herdr transport.
