# M3.5 — Diff Settings & Command Cleanup

## Current Contract

User authorization post-`e923e7e`; supersedes historical policy of
exclusively manual opening and fallback alias. Does not start M4 or redesign dock.

| Preference | Default | Behavior |
|---|---|---|
| Dock width | 45% | 30–60%, 1% steps in settings; resize preserves minimums of 34 dock columns and 46 conversation. At 90 columns available space prevails over percentage. |
| Line numbers | On | Off hides numeric gutter only; preserves signs, old/new ranges, and appended content. |
| File paths | Smart | Smart: middle elision by columns; Full: relative path with trailing truncation; Filename: basename. Preserves two lines and real path in appended context/inspection. |
| Collapse files by default | On | Applied when loading new view identity; changing preference does not undo current expansions/selection. |
| Remember dock width | On | Saves ratio upon drag end, keyboard action, or manual close. Off leaves transient resize: reopening uses configured Dock width. |
| Auto-open after iteration | Off | Explicit consent in settings only. Opens after complete individual capture settled; never during capture, error, abort, grouping, or partial. Does not take focus or alter draft. |

`/diff` toggles dock; F6 opens/focuses. `/iteration-diff` removed. Upon foreign
`/diff`, collision reported without registering or creating alias; F6 remains available.
Manually closing during capture or post-result prevents reopening for that
window. Duplicate settled events do not reopen. Activating On does not retroactively open.

## Public API and Persistence Scope

Pi 1.4.0: `ctx.ui.custom` overlay + `SettingsList`, following official example
`examples/extensions/tools.ts`; no custom editor. `appendEntry` stores exclusively
v1 payload of six preferences, outside model context. `getBranch`
restores upon start/resume/reload or navigating tree. No contents,
diffs, paths, or global config written. New session without entry: defaults.
Fork inherits entries from its branch; navigating another branch recovers its preferences.
Invalid/unknown payload resets defaults, including auto-open Off.
Without persistent session (`--no-session`), no inter-process persistence.

Public limit: Pi offers no arbitrary global storage of extension
preferences. Per-branch persistence chosen, without own filesystem or dependencies.
Existing layout adapter remains sole internal boundary. Ratio
no longer a module global variable and not shared between panes/sessions.

## M4.4 Update (2026-10-24)

Prior section describes historical M3.5 contract. M4.4 changes **only**
`Dock width` and `Remember dock width`: Pi 1.4.0 exposes no arbitrary global
storage for extensions (`docs/extensions.md`, State), but exports
`getAgentDir()`; extension stores `{version, dockWidth, rememberWidth}` in
`<agent-dir>/iteration-diff.json` (`~/.pi/agent` normally, or
`PI_CODING_AGENT_DIR`). Global per user/agent directory, shared
across projects, branches, sessions, and Pi/Herdr processes. `settings.json` is not edited.
Historical decision: other preferences, including `Auto-open`, were per-branch. As of 2026-10-27, an explicitly toggled `Auto-open` is saved in the same local file and overrides branch values across sessions; legacy files without the field retain branch behavior until toggled.

On saves upon drag end or changing width with keyboard/settings; Off keeps
saved width without updating it with drag, and subsequent opens
use 45%. Returning to On recovers last saved width if new one
not explicitly chosen. Installation without global file takes valid
width from prior branch and migrates it once; invalid/inaccessible file
uses 45%/On, warns, and does not alter auto-open. Atomic write by renaming
temporary 0600 file in same directory, without watchers or dependencies;
last writer among concurrent processes wins. On Windows, final permissions
depend also on inherited ACLs. Without file or inherited width, nothing
is written until width or Remember changes. Requested width may
cede to layout minimums in narrow terminal.
