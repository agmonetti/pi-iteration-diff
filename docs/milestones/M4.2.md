## Defecto confirmado

- **Reproducción:** expandir `a.ts` y `b.ts`, seleccionar por mouse una línea de `b.ts`, colapsar `a.ts` por mouse y pulsar `a`. `DiffPanel.rebuild()` reconstruía filas pero mantenía los índices numéricos de selección. La línea de `b.ts` pasaba a otra posición; `formatSelectedContext()` devolvía `undefined` (o podía apuntar a una fila distinta), perdiendo el fragmento pretendido.
- **Causa:** anchor/focus referían índices del array anterior, no identidades de fila. El test dirigido `collapsing a preceding file does not retarget a selected line` falló **antes** de cambiar el código (`undefined` frente a `[b.ts | diff | new:1]\n+second`) y pasó después. Se corrigió únicamente el remapeo al reconstruir por ruta/tipo/ordinal; si falta un extremo, se invalida la selección. Reemplazar el contenido bajo la misma key con otro objeto de vista también limpia selección antigua (regresión dedicada).
- **Consecuencia de seguridad:** ninguna mutación de archivos/Git ni autoenvío; podía anexar contexto erróneo o no anexar nada. El test comprueba que el borrador previo permanece y se anexa el fragmento correcto tras colapsar.
- **Límite:** la selección por fila sigue siendo un rango contiguo, no un conjunto de rangos persistentes por archivo. Los riesgos previos de M4.1 (encabezado multi-hunk y Shift+Down desde header/path) no fueron reproducidos/corregidos aquí; requieren casos dirigidos antes de declararlos defectos confirmados.
