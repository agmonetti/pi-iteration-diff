## 1. Manifiesto y Packaging (M5.1)

El archivo `package.json` fue configurado siguiendo las especificaciones oficiales de Pi Packages:

- **Identidad del paquete**: `name: "pi-iteration-diff"`, `version: "0.1.0"`, `type: "module"`, `main: "src/index.ts"`.
- **Manifiesto Pi**: `"pi": { "extensions": ["./src/index.ts"] }`.
- **Discovery**: `"keywords": ["pi-package"]` para registro e indexación en la galería de paquetes de Pi.
- **Dependencias**:
  - `dependencies`: ninguna dependencia externa en runtime. El código utiliza exclusivamente módulos estándar de Node.js (`node:fs`, `node:path`, `node:crypto`, `node:child_process`, `node:os`, `node:util`).
  - `peerDependencies`: declara `@earendil-works/pi-coding-agent: "*"` y `@earendil-works/pi-tui: "*"` como provistos por el host, evitando copias físicas duplicadas o colisiones de registro según las directrices oficiales.
  - `devDependencies`: herramientas de desarrollo, tipado y test (`typescript`, `tsx`, `@types/node`, `@earendil-works/*`).
- **Lista de distribución (`files`)**: restringe el empaquetado exclusivamente a:
  - `src/`
  - `README.md`
  - `LICENSE`
  - `package.json`
  Quedan fuera del tarball: `tests/`, documentación de desarrollo (`M*.md`, `PROGRESS.md`, `REQUIREMENTS.md`, `RESEARCH.md`), scripts de prueba y artefactos de trabajo.

## 2. Instalación y Descubrimiento (M5.2)

Se verificó el soporte de los mecanismos de instalación nativos de Pi:

1. **Instalación Git nativa**:
   ```bash
   pi install git:github.com/agmonetti/pi-iteration-diff
   ```
   Pi clona el repositorio en `<agent-dir>/git/...` y ejecuta `npm install --omit=dev --legacy-peer-deps`. Al no tener dependencias de producción externas, la instalación es inmediata y libre de conflictos de peers.

2. **Instalación local / proyecto**:
   ```bash
   pi install ./path/to/pi-iteration-diff
   pi install ./path/to/pi-iteration-diff -l   # En .pi/settings.json
   ```

3. **Carga sin `-e`**:
   Pi descubre el punto de entrada a través de `package.json` (`pkg.pi.extensions = ["./src/index.ts"]`). Los comandos `/diff` y `/diff-settings` quedan registrados automáticamente en la sesión interactiva.

4. **Preservación de configuración**:
   La persistencia global del dock (`<agent-dir>/iteration-diff.json`, permisos `0600`) permanece desacoplada del ciclo de vida del paquete: no se borra ni se modifica al reinstalar, actualizar o desinstalar la extensión.

### Diagnóstico de Fallos en `tests/package-install.test.ts`

Los 144 tests de funcionalidad de producto (snapshots, diffs, visor TUI, adapter, settings, persistencia de dock width, Git intacto, etc.) pasaron con 100% de éxito en las 3 plataformas. Los únicos fallos se debieron a supuestos del entorno en las aserciones del nuevo test:

1. **Aserción de nombre de carpeta en `pi list` (Ubuntu, macOS, Windows)**:
   - *Causa*: El test local evaluaba `assert.match(listRes.stdout, /pi-diff/)`, asumiendo el nombre de la carpeta de desarrollo local (`.../Documentos/pi-diff`).
   - *Comportamiento en CI*: En GitHub Actions el repositorio se clona como `pi-iteration-diff` (`/home/runner/work/pi-iteration-diff/pi-iteration-diff`). El listado reporta `pi-iteration-diff`, no `pi-diff`.
   - *Corrección identificada*: Evaluar coincidencia con `pi-iteration-diff` o `basename(ROOT)`.

2. **Ejecución de `npm` en Windows (Windows-only)**:
   - *Causa*: `execFileSync("npm", ["pack", ...])` lanza `ENOENT` en Windows nativo porque el ejecutable es `npm.cmd`.
   - *Corrección identificada*: Invocar con `process.platform === "win32" ? "npm.cmd" : "npm"` o `{ shell: true }`.

Por restricciones estrictas de la consigna («no hacer un segundo push sin autorización»), el código del repositorio permanece intacto y la corrección queda lista para aplicarse en cuanto sea autorizada.
