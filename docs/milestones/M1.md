UI frozen: no viewer, hunks, history, or drag/drop. Pi 1.4.0, TypeScript strict,
Node 26.12.0/Linux as development environment. Target product: Linux, macOS, and
native Windows (NFR-10). No new dependencies. Portability fix
implemented and **cross-platform certification completed** via real CI
(GitHub Actions run 40018853023 on commit `116b6a8`); see final matrix.

## Capture and Scope

- `workspaceRoot` resolves real worktree root with Git; outside Git, root `/`
  or full HOME: unavailable. Includes eligible tracked and untracked, even dirty
  and prior staged; does not use HEAD as content or write index/objects/history.
- Git `ls-files` respects standard ignores (also ignored tracked). Ignored paths/prefixes
  are logged so changing `.gitignore` does not invent creations.
  Does not traverse submodule content or other worktrees.
- Only regular UTF-8 files without NUL, without symlinks/hardlinks/specials. Node
  shared engine with bigint `lstat`/`fstat` and pre/post-read validation;
  no global macOS/Windows rejection. Linux keeps an additional procfs
  descriptor check; macOS/Windows do not execute or require that check.
  Particular guarantees and residual races: portability section at the end.
- Segment exclusions: `.env*`, `.ssh`, `.gnupg`, `.aws`, `.azure`, `.kube`,
  `.npmrc`, `.netrc`, `.pypirc`, `credentials.*`, `secret(s).*`, id_rsa/
  ed25519/ecdsa keys, and pem/key/p12/pfx/keystore extensions. Conservative content filter:
  private key headers and long api-key/token/client-secret/password assignments.
  `exclude` supports literal relative prefixes. **Not a universal secret detector**:
  arbitrary text may contain sensitive data and filter operates post-read in RAM.
- No persistence or content/prompts logs. Release by dropping references,
  no promise of heap zeroization or physical erasure.

## Configurable Limits (`CaptureLimits`)

| Limit | Default per Endpoint |
|---|---|
| Candidate files / ignored prefixes | 10,000 each group |
| Individual file | 1 MiB |
| Retained content | 16 MiB (+ up to 1 byte per file) |
| Output per enumeration command | 2 MiB |
| Depth | 32 segments |
| Time | 2000 ms |

Sequential reads, never `readFile` without limit. Reading buffer is bounded
to validated size +1 to detect growth; transient decoding per file.
Git stdout is bounded and direct subprocess receives `kill("SIGKILL")` upon
timeout/cancellation/excess (Node forced termination on Windows); `close` is awaited.
Only metadata commands executed, without shell/pager/fsmonitor or inherited
Git overrides. Contract presumes reliable Git executable in PATH; not a
general supervisor of process trees of malicious executables/configuration.
Maps, lists, and path strings have bounds derived from stdout and maxFiles, plus
content; `maxBytes` is not a bound on total Node/Pi RSS. Two endpoints maximum
per window; delta reuses buffers without duplicating code.
Defaults limit work, not promising universal latency: filesystem metadata
is not cancellable in Node (blocked FS can exceed deadline). Check deadline
between operations; stop capturing upon expiration. No atomic snapshot against
external processes, nor forensic protection against malicious workspace writer.

## Result Contracts

`Snapshot`: temporal interval, root, observed bytes, omissions per path/prefix,
enumeration coverage, and content-less incidents. `NetDelta`: creations,
modifications, and deletions by byte equality, before/after references.
Missing endpoint is only absence if fully enumerated and path was not omitted.
If evidence missing, that change is omitted and result is `partial`, never empty
complete. No rename/modes detection: observable rename = delete + create.
Binaries, invalid formats, limits, races, or failed I/O remain explicit.

## Lifecycle ADR-003 (Public Pi 1.4.0)

`registerCaptureLifecycle` returns typed `IterationCapture`, wired in
`src/index.ts` silently. UI spike remains synthetic and does not read this
result until M2. Editor, selection, and product commands unchanged.

| Signal | Action |
|---|---|
| `session_start` | Invalidate generation; resolve session ID + worktree realpath |
| `input` idle interactive/rpc | Candidate and baseline completed, awaited before proceeding |
| `before_agent_start` user | Confirm text SHA-256 fingerprint; window with epoch and sequence |
| No candidate / transformation / expansion / images / source extension / custom | Unverifiable late baseline, never complete individual |
| Extra input or second user message_start | Conservative grouping even if consumed/rejected later |
| `turn_end` / `agent_before_settle` | Observe outcome, never close or re-baseline |
| `agent_end` / retries | Do not close or change baseline |
| `agent_settled` | Verify scope, capture final, and compare; abort/unsuccessful error |
| `session_shutdown` / session/cwd/root change / reload | Sync invalidation, AbortController, discard old publication |

Text fingerprint only in memory, no prompts or logs hashes. Images treated
conservatively as unverifiable because runtime may normalize them.
Other handlers may transform/consume input; single candidate does not publish
an iteration. No public event confirms consumption/failed preflight:
candidate remains bounded until next input or invalidation.
To limit retention, new candidate releases prior result; if
consumed, no result invented nor old Last iteration recovered.

Serialized reads by controller, including aborted generation still
finishing I/O; cancellation/invalidation never waits for queue. Window identity
verification after each await prevents obsolete publication. Another runtime upon
reload has another epoch; resume does not rebuild conversation history buffers.
Class shares no global state between sessions/panes/worktrees.

`CaptureState` exposes `individual` only when window finished successful, isolated,
and complete. Otherwise exposes `unavailable` with reason and, if present, `window`:
`grouped` (Batch Net), `unverified`, `partial`, `cancelled`, or `failed`. Do not confuse
Batch Net with Current Working Tree nor with individual request.
`CapturedWindow` keeps intervals, omissions, and delta referencing same
buffers. No history or fallback to prior window.
Changes are **observed**; another extension prior to hook or external process
may write outside/inside window. Pi authorship not certified.

## Final Acceptance Audit — 2026-10-23 (16:55 UTC−03)

**Ruling: M1 ACCEPTED**, limited to engine and approved M1 ADR-003 contract.
Does not authorize or initiate M2. Review of four capture/lifecycle units,
`src/index.ts`, and their suites. Two defects reproduced and fixed with regressions:

1. `ENOENT` on `open` after successful `lstat` was treated as complete absence.
   Regression eliminates a tracked file right before real open: FAIL before
   (no omission), PASS after. Only initial absence remains valid deletion;
   if file already observed, race is omitted and delta is partial.
2. An `input` could continue with `true` of an already invalidated synchronization.
   Regression with controlled dispatch and shutdown in a microtask after resolving scope:
   FAIL before (overwrites `session-shutdown` with `input-not-confirmed`), PASS after.
   Synchronization now returns its generation and three consumers verify it
   after await. No file leakage between sessions demonstrated in real Pi.
