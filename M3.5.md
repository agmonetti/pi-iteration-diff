# M3.5 — Diff Settings & Command Cleanup

## Contrato vigente

Autorización del usuario posterior a `e923e7e`; sustituye la política histórica de
apertura exclusivamente manual y alias fallback. No inicia M4 ni rediseña el dock.

| Preferencia | Default | Comportamiento |
|---|---|---|
| Dock width | 45% | 30–60%, pasos de 1% en ajustes; resize conserva mínimos de 34 columnas dock y 46 conversación. A 90 columnas el espacio disponible prevalece sobre el porcentaje. |
| Line numbers | On | Off oculta sólo gutter numérico; conserva signos, rangos old/new y contenido anexado. |
| File paths | Smart | Smart: elisión media por columnas; Full: ruta relativa con truncado final; Filename: basename. Conserva dos líneas y ruta real en contexto anexado/inspección. |
| Collapse files by default | On | Se aplica al cargar una nueva identidad de vista; cambiar preferencia no deshace expansiones/selección actuales. |
| Remember dock width | On | Guarda ratio al terminar arrastre, acción de teclado o cierre manual. Off deja resize transitorio: reapertura usa Dock width configurado. |
| Auto-open after iteration | Off | Sólo consentimiento explícito en ajustes. Abre tras settled de captura individual completa; nunca durante captura, error, aborto, agrupación o parcial. No toma foco ni altera borrador. |

`/diff` alterna dock; F6 abre/enfoca. `/iteration-diff` eliminado. Ante `/diff`
ajeno, se informa colisión sin registrarlo ni crear alias; F6 sigue disponible.
Cerrar manualmente durante captura o tras resultado impide reapertura para esa
ventana. Eventos settled duplicados no reabren. Activar On no abre retroactivamente.

## API pública y alcance de persistencia

Pi 1.4.0: `ctx.ui.custom` overlay + `SettingsList`, siguiendo ejemplo oficial
`examples/extensions/tools.ts`; no editor propio. `appendEntry` guarda exclusivamente
payload v1 de seis preferencias, fuera del contexto del modelo. `getBranch`
restaura al iniciar/reanudar/recargar o navegar árbol. No se escriben contenidos,
diffs, rutas ni configuración global. Nueva sesión sin entrada: defaults.
Fork hereda entradas de su rama; navegar otra rama recupera sus preferencias.
Payload inválido/desconocido restablece defaults, incluido auto-open Off.
Sin sesión persistente (`--no-session`) no hay persistencia entre procesos.

Limitación pública: Pi no ofrece almacenamiento global arbitrario de preferencias
de extensión. Se elige persistencia por rama, sin filesystem propio ni dependencias.
El adaptador de layout existente sigue siendo la única frontera interna. El ratio
ya no es variable global de módulo y no se comparte entre panes/sesiones.
