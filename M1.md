# M1 — Motor efímero y delta observado

UI congelada: sin visor, hunks, historial ni drag/drop. Pi 1.4.0, TypeScript strict,
Node 26.12.0/Linux. No dependencias nuevas.

## Captura y alcance

- `workspaceRoot` resuelve el root real del worktree con Git; fuera de Git, root `/`
  o HOME completo: indisponible. Incluye tracked y untracked elegibles, incluso dirty
  y staged anteriores; no usa HEAD como contenido ni escribe índice/objetos/historia.
- Git `ls-files` respeta ignores estándar (también tracked ignorados). Se registran
  rutas/prefijos ignorados para que cambiar `.gitignore` no invente creaciones.
  No se recorre contenido de submódulos ni otros worktrees.
- Sólo archivos regulares UTF-8 sin NUL, sin symlinks/hardlinks/especiales. Se validan
  padres, inode/dev/tamaño/timestamps y descriptor `/proc/self/fd` **antes de leer**.
  Captura segura de contenidos actualmente soportada sólo en Linux con procfs;
  otro entorno produce omisiones explícitas, no un resultado completo.
- Exclusiones por segmentos: `.env*`, `.ssh`, `.gnupg`, `.aws`, `.azure`, `.kube`,
  `.npmrc`, `.netrc`, `.pypirc`, `credentials.*`, `secret(s).*`, claves id_rsa/
  ed25519/ecdsa y extensiones pem/key/p12/pfx/keystore. Filtro conservador de contenido:
  cabeceras de clave privada y asignaciones largas api-key/token/client-secret/password.
  `exclude` admite prefijos relativos literales. **No es detector universal de secretos**:
  texto arbitrario puede contener datos sensibles y el filtro opera tras lectura en RAM.
- Sin persistencia ni logs de contenidos/prompts. Liberación por soltar referencias,
  no promesa de zeroization del heap ni borrado físico.

## Límites configurables (`CaptureLimits`)

| Límite | Default por endpoint |
|---|---|
| Archivos candidatos / prefijos ignorados | 10 000 cada grupo |
| Archivo individual | 1 MiB |
| Contenido retenido | 16 MiB (+ hasta 1 byte por archivo) |
| Salida por comando de enumeración | 2 MiB |
| Profundidad | 32 segmentos |
| Tiempo | 2000 ms |

Lecturas secuenciales, nunca `readFile` sin límite. El buffer de lectura está acotado
al tamaño validado +1 para detectar crecimiento; decodificación transitoria por archivo.
Git stdout está acotado y el subproceso recibe SIGKILL al timeout/cancelación/exceso.
Mapas, listas y cadenas de rutas tienen cotas derivadas de stdout y maxFiles, además
del contenido; `maxBytes` no es una cota del RSS total de Node/Pi. Dos endpoints como
máximo por ventana; el delta reutiliza sus buffers sin duplicar código.
Los defaults limitan trabajo, no prometen latencia universal: metadata filesystem
no es cancelable en Node (un FS bloqueado puede superar el plazo). Comprobar plazo
entre operaciones; no seguir capturando al vencer. No hay snapshot atómico frente
a procesos externos, ni protección forense contra un escritor malicioso del workspace.

## Contratos de resultado

`Snapshot`: intervalo temporal, raíz, bytes observados, omisiones por ruta/prefijo,
cobertura de enumeración e incidencias sin contenido. `NetDelta`: creaciones,
modificaciones y eliminaciones por igualdad de bytes, referencias before/after.
Un endpoint faltante sólo es ausencia si se enumeró entero y la ruta no fue omitida.
Si falta evidencia, se omite ese cambio y el resultado es `partial`, nunca vacío
completo. No hay detección de renames/modos: rename observable = borrar + crear.
Binarios, formatos inválidos, límites, carreras o IO fallido quedan explícitos.

## Lifecycle ADR-003 (Pi público 1.4.0)

`registerCaptureLifecycle` devuelve un `IterationCapture` tipado, conectado en
`src/index.ts` de forma silenciosa. El spike UI sigue sintético y no lee este
resultado hasta M2. No se cambia editor, selección ni comandos de producto.

| Señal | Acción |
|---|---|
| `session_start` | Invalidar generación; resolver session ID + realpath worktree |
| `input` idle interactive/rpc | Candidato y baseline completado, awaited antes de seguir |
| `before_agent_start` user | Confirmar huella SHA-256 del texto; ventana con epoch y secuencia |
| Sin candidato / transformación / expansión / images / source extension / custom | Baseline tardío no verificable, nunca individual completo |
| Input extra o segundo message_start user | Agrupación conservadora incluso si luego se consume/rechaza |
| `turn_end` / `agent_before_settle` | Observar outcome, nunca cerrar ni rebaselinar |
| `agent_end` / retries | No cerrar ni cambiar baseline |
| `agent_settled` | Verificar scope, capturar final y comparar; aborto/error no exitoso |
| `session_shutdown` / cambio session/cwd/root / reload | Invalidación síncrona, AbortController, descartar publicación vieja |

Huella del texto sólo en memoria, sin prompts ni hashes en logs. Imágenes se tratan
conservadoramente como no verificables porque el runtime puede normalizarlas.
Otros handlers pueden transformar/consumir input; un candidato solo no publica
una iteración. No hay evento público que confirme que fue consumido/preflight
falló: el candidato queda acotado hasta el siguiente input o invalidación.
Para limitar retención, un nuevo candidato libera el resultado previo; si se
consume, no se inventa resultado ni se recupera un Last iteration viejo.

Lecturas serializadas por controlador, incluida una generación abortada que todavía
está terminando IO; cancelación/invalidation nunca espera la cola. Verificación de
identidad de ventana tras cada await impide publicación obsoleta. Otro runtime al
reload tiene otro epoch; resume no reconstruye buffers del historial de conversación.
La clase no comparte estado global entre sesiones/panes/worktrees.

`CaptureState` sólo expone `individual` cuando la ventana terminó exitosa, aislada
y completa. En otro caso expone `unavailable` con motivo y, si existe, `window`:
`grouped` (Batch Net), `unverified`, `partial`, `cancelled` o `failed`. No confundir
el Batch Net con Current Working Tree ni con una petición individual.
`CapturedWindow` conserva intervalos, omisiones y el delta con referencias a los
mismos buffers. No existe historial ni fallback a una ventana anterior.
Son cambios **observados**; otra extensión anterior al hook o un proceso externo
puede escribir fuera/dentro de la ventana. No se certifica autoría de Pi.

## Evidencia automatizada de M1

- SDK AgentSession real con stream local: write/edit/bash y custom tool, dos
  iteraciones y vacío neto, steer/followUp agrupados, retry, aborto/error definitivo,
  input consumido/transformado, preflight fallido y reload.
- Adaptador HTTP real con loopback: 429→200, bash abortado, recuperación, reapertura
  de sesión y otra sesión; sin credenciales reales ni red remota. M1 se conecta a los
  fixtures HTTP de M0, que conservan también sus aserciones anteriores.
- Controlador con capturas detenidas: invalidar baseline/final, session scope y
  serialización, doble settled, omisiones y fallos. No fabricar una traza runtime
  a partir de estos unitarios: las pruebas SDK/HTTP aportan esa evidencia aparte.
- Medición local (suite concurrente, Linux/Node 26.12.0): 512 archivos × 4 KiB,
  2 097 152 bytes retenidos; 373.6 ms de captura. RSS del proceso de test 100 929 536
  bytes: incluye runtime/harness, no es memoria incremental del motor ni un SLA.
- No pruebas humanas nuevas de Pi/Herdr para M1 ni certificación de otros sistemas
  operativos. M0 humano permanece válido sólo para su alcance; M2 no iniciado.

## Auditoría final de aceptación — 2026-10-23 (16:55 UTC−03)

**Dictamen: M1 ACCEPTED**, limitado al motor y al contrato ADR-003 aprobado para M1.
No autoriza ni inicia M2. Revisión de las cuatro unidades de captura/lifecycle,
`src/index.ts` y sus suites. Dos defectos reproducidos y corregidos con regresiones:

1. `ENOENT` de `open` tras un `lstat` exitoso se trataba como ausencia completa.
   Una regresión elimina un archivo tracked justo antes del open real: FAIL antes
   (sin omisión), PASS después. Sólo la ausencia inicial sigue siendo borrado válido;
   si ya se observó el archivo, la carrera queda omitida y el delta es parcial.
2. Un `input` podía continuar con el `true` de una sincronización ya invalidada.
   Regresión con dispatch controlado y shutdown en una microtask tras resolver scope:
   FAIL antes (sobrescribe `session-shutdown` con `input-not-confirmed`), PASS después.
   La sincronización devuelve ahora su generación y los tres consumidores la verifican
   después de await. No se demostró fuga de archivos entre sesiones en Pi real.
